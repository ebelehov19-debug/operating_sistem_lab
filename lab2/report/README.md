## Лабораторная работа №2

### Создание процессов и взаимодействие через каналы

ФИО: Белехов Егор Евгеньевич

Группа: 201

Вариант: 17

### Цель работы

Приобрести практические навыки создания дочерних процессов, обмена данными через
неименованные каналы, перенаправления стандартных потоков и управления ресурсами
операционной системы Linux. Среда сборки и запуска — Ubuntu в WSL.

### Постановка задачи

Разработать программу на языке Си. Родительский процесс создаёт два дочерних
процесса и передаёт им строки произвольной длины через два неименованных канала.
Строки длиной не больше 10 символов направляются первому ребёнку, строки длиной
больше 10 символов — второму. Каждый ребёнок удаляет из полученных строк
английские гласные `aeiouAEIOU` и записывает результат в свой файл.

Имена двух выходных файлов вводятся первыми двумя строками. Длина текста
определяется до удаления гласных, без завершающего перевода строки.
Необходимо обрабатывать ошибки, закрывать дескрипторы, освобождать динамическую
память и дожидаться завершения обоих дочерних процессов.

### Алгоритм решения

1. Родитель регистрирует функцию резервной очистки через `atexit`, игнорирует
   `SIGPIPE` для обработки ошибки записи `EPIPE` и читает два имени файлов
   с помощью `getline`. Пустые и одинаковые строки имён отклоняются.
2. Создаёт два канала через `pipe` и два дочерних процесса через `fork`.
   В каждом ребёнке перенаправляет стандартный ввод на его канал через `dup2`,
   закрывает ненужные дескрипторы и запускает программу `child` через `execv`.
   Имя соответствующего выходного файла передаётся аргументом запуска.
3. Каждый ребёнок открывает свой файл для записи с флагами
   `O_WRONLY | O_CREAT | O_TRUNC` и перенаправляет в него стандартный вывод.
   Диагностические сообщения с PID направляются в `stderr`.
4. Родитель построчно читает текст через `getline`, динамически увеличивающую
   буфер. Функция `utf8_length` считает кодовые точки корректного UTF-8.
   По длине исходной строки выбирается первый или второй канал.
5. Ребёнок читает строки из своего стандартного ввода и удаляет гласные
   в исходном буфере двумя указателями. Функция `safe_write_all` записывает
   обработанную строку и перевод строки, учитывая частичные записи и `EINTR`.
6. После окончания ввода родитель закрывает концы каналов для записи.
   Дети дочитывают данные, получают EOF, закрывают файлы и освобождают буферы.
   Родитель получает статусы обоих детей через `waitpid`. Успех возвращается
   только при успешном завершении обоих детей.

Используются две программы — `parent` и `child`. Программа `child` запускается
дважды в отдельных процессах с разными каналами ввода и выходными файлами.
Общие функции находятся в `src/io.c`, их объявления — в `src/io.h`.

### Ввод и вывод программы

Ввод: две строки с именами разных выходных файлов, затем строки текста.
Длина строк не ограничена фиксированным буфером; возможный размер зависит
от доступной памяти. Завершение ввода в терминале Ubuntu — `Ctrl+D` на пустой строке.

Вывод: обработанные строки в двух файлах. В первом находятся результаты строк
длиной не больше 10 символов, во втором — результаты более длинных строк.
Буква `y`, русские буквы, цифры и знаки препинания сохраняются.
Диагностика показывает PID родителя и детей, выбранный канал и статусы завершения.

Сборка и запуск из корня лабораторной:

```bash
cmake -S . -B build
cmake --build build
cd build
./parent
```

Пример вводимых данных:

```text
short.txt
long.txt
Hello
abcdefghij
Hello world!
```

После последней строки ввод завершается. Ожидаемое содержимое `short.txt`:

```text
Hll
bcdfghj
```

Ожидаемое содержимое `long.txt`:

```text
Hll wrld!
```

Строка `abcdefghij` содержит ровно 10 символов и направляется первому ребёнку.
После завершения процессов выходные файлы сохраняются. Повторный запуск
с теми же именами файлов очищает их прежнее содержимое.

### Вывод

Реализована обработка строк двумя дочерними процессами с передачей данных через
два неименованных канала. Строки распределяются по исходной длине, английские
гласные удаляются, а результаты сохраняются в отдельных файлах. Освоены создание
процессов через `fork`, запуск дочерних программ через `execv`, перенаправление
стандартных потоков и управление файловыми дескрипторами. Обработаны частичные
записи и прерывания записи и ожидания сигналами; динамическая память освобождается
после использования. Ожидание обоих детей через `waitpid` предотвращает сохранение
зомби-процессов при штатном завершении.
